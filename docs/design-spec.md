# SEO Routine Skill — Design Spec

**Version:** 2.0 (config version 4)
**Goal:** A reusable, project-agnostic `/seo-routine` skill that grows organic traffic through a measured
weekly cycle (analyze → plan → implement → verify → review) and reports what worked without flattering
itself.

## 1. Architecture

Two layers:

- **Core engine** (this plugin): `SKILL.md` routes a request to a phase and a reference. The references
  hold the rules (measurement, experiments, delivery, GEO). Scripts collect data. Templates scaffold a
  project.
- **Project adapter** (generated by `calibrate`): `seo-config.md` plus a ledger, goals, learnings and
  dated run folders under `{root}/`, version-controlled in the target repository.

`SKILL.md` stays short and routes. Rules live in exactly one reference file, and the skill and this spec
point at them instead of restating them.

## 2. State model

Repository files are the source of truth. Claude memory is optional retrieval context and never
overrides a setting or a status.

| Artifact | Owns |
|---|---|
| `seo-config.md` (v4) | Effective settings, source locations, budgets, publishers, GEO panel reference |
| `experiments.json` | Experiment IDs, predictions, delivery state, verification state, evaluation |
| `goals.md` | The active strategic goal and archived previous goals |
| `learnings.md` | Decisions and corrections, with evidence, newest first |
| `geo-panel.json`, `geo-scorecard.md` | The fixed AI-answer panel and its dated readings |
| `weeks/<ISO-week>/<run-date>/` | Per-run inputs, analysis, plan, changes, changesets, verify, review |

A pre-v4 `forward-log.md` and scorecard are historical evidence, referenced by `legacy_forward_log` and
never auto-migrated.

## 3. Principles (and the v1 designs they replaced)

| v2 rule | v1 behavior it replaces | Why |
|---|---|---|
| Rank by recorded evidence: mechanism, alternative cause, refuting observation | A 0-100 composite of six weighted signals | Composite scores need inputs the sources do not have (volumes, CTR benchmarks) and hide the reasoning |
| No automatic weight tuning | Reweighting signals from the last handful of predictions | Heterogeneous predictions on small samples teach nothing |
| Budgets are maxima; zero is valid | "3-5 content and 2-3 technical changes per week" | A quota manufactures experiments with no expected benefit |
| Repairs are recorded as repairs | Everything scored as a growth prediction | A correct fix is not a traffic claim |
| Score direction and progress against a declared target; Hit / Partial / Miss counted separately | Absolute size of the change; accuracy = (Hit + Partial) / total | Absolute deltas reward movement in the wrong direction; folding Partial into success inflates accuracy |
| Delivery, live verification and outcome are separate states | One "Published" status | A PR is not a deploy, and a deploy is not live verification |
| Independent adversarial review before publishing | Diff glance by the author | The author cannot catch their own false claims |
| Failed source is a gap, not zero; finalized GSC data; property totals with query coverage | Latest-available data; page and query rows treated as totals | Truncation and anonymization silently change the answer |
| GEO panel as a versioned instrument beside real referral outcomes | Quoted percentage uplifts from a 2023 benchmark | The uplifts are lab figures, not forecasts for a given site |

## 4. Phases

Each phase's contract lives in its reference. This table shows only what each one must leave behind.

| Phase | Reference | Leaves behind |
|---|---|---|
| calibrate | `SKILL.md` | v4 config, scaffolded root, `.env.seo` placeholders, tested sources, recorded gaps |
| analyze | `measurement.md` | `analysis.md` and sanitized `inputs/` with windows, freshness, timezone and failures |
| plan | `experiments.md` | `plan.md` and ledger records with predeclared baselines, targets, comparators and horizons |
| implement | `delivery.md` | Commits, `changes.md` (checked commit, commands, results), changesets, independent review result |
| publish | `delivery.md` | The authorized action done and verified; PR URL and deploy status recorded separately |
| verify | `delivery.md` | `verify.md` with expected/observed values, timestamps and the deployed SHA |
| review | `experiments.md` | `review.md`, updated ledger, growth hit rate with its denominator, learnings |
| geo | `geo.md` | Raw receipts in `inputs/`, a versioned `geo-scorecard.md` row, referral outcomes |
| autopilot | `SKILL.md` | All of the above, each with an evidence-backed state including "no change" and "pending" |

## 5. Data collection

| Source | Method | Notes |
|---|---|---|
| Search Console | `scripts/gsc.py` | Finalized web data, property totals, brand/nonbrand/unreported query partition, row-cap state, equal-window comparison |
| Analytics | Provider API or a project collector | Visit-level cohorts, entry assigned before filtering, half-open UTC windows |
| GA4 | `scripts/ga4.py` | Cross-check only |
| DataForSEO | Bundled scripts | 2 req/s, exponential backoff |
| AI answers | `scripts/geo_panel.py` | Fixed panel, raw receipt per call |
| Ahrefs | Manual CSV drops in `inputs/` | Optional |
| Self-crawl | Fetch and parse | Changed URLs plus an evidence-led sample; 2 req/s; Core Web Vitals via PageSpeed Insights |

## 6. Packaging

```
seo-routine/                          # marketplace repository
├── .claude-plugin/marketplace.json
├── skills/seo-routine/               # the plugin
│   ├── .claude-plugin/plugin.json
│   ├── SKILL.md
│   ├── references/                   # measurement, experiments, delivery, geo + SEO/GEO background
│   ├── scripts/                      # Python collectors (stdlib for DataForSEO; Google libs for GSC/GA4)
│   ├── templates/                    # scaffolding used by calibrate
│   └── skills-ref/                   # gap-finder, competitor-intel, brand-writer notes
├── docs/design-spec.md
└── README.md
```

Install with `/plugin marketplace add vladuma/seo-routine` then `/plugin install seo-routine@vladuma`. The
plugin has no runtime dependency on other skills, and `calibrate` is the only setup step.

## 7. Safety and boundaries

- Credentials come only from `.env.seo` and the paths it names, and are never printed or persisted.
- Publishing is limited to the configured, authorized action. `autonomous` and `autopilot` never widen
  permissions, and the skill never merges, deploys or edits schedules on its own.
- If a push to the base branch deploys production, the push is the deployment.
- A request to commit only stays local and is reported as `local_only`.
- Reviewers are read-only and cannot change branches or commits.
